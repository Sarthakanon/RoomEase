RoomEase Full Settings Flow (A to Z)

Technical Summary Paragraph

RoomEase Settings is a user-control surface that combines account actions (change password, logout), roomspace management shortcuts (switch/create/join/leave), and app behavior configuration (payment-detection notification settings, monitoring permissions toggles). Architecturally, it is frontend-driven through SettingsScreen and related service/provider calls, with selective backend persistence where needed (profile fetch, session logout, roomspace APIs, payment notification records). Password security flows remain Firebase-auth native (reauth + update), while backend session lifecycle is independently managed via /api/auth/logout cookie invalidation.

1. Main settings frontend files

  1. lib/features/settings/presentation/settings_screen.dart - Main settings page UI - Loads Firebase user + backend profile - Exposes change password, payment detection settings, roomspace controls, logout

  2. lib/features/settings/presentation/payment_notification_settings_screen.dart - Settings for payment auto-detection feature - Enables/disables detection, notification monitoring, SMS monitoring - Manages minimum amount and allowed apps/merchants

  3. lib/services/firebase_auth_service.dart - Implements changePassword(...) and Firebase signout

  4. lib/providers/roomspace_provider.dart - Roomspace state load/refresh/leave/clear from settings actions

  5. lib/services/api_service.dart - Backend logout and roomspace API calls used by provider/service chain

2. Settings data-load flow

When Settings opens: 1. SettingsScreen.initState() calls _loadUserData() 2. Reads Firebase current user (FirebaseAuthService.currentUser) for quick name/email baseline 3. Calls _cachedApiService.getUserProfile() to sync name/email from backend profile 4. Calls RoomspaceProvider.loadRoomspaces() to show active roomspaces and management options

Result: - Settings screen reflects Firebase identity + backend profile + current roomspace context.

3. Change password flow

UI trigger: - SettingsScreen._showChangePasswordDialog()

Execution path: 1. User enters current/new/confirm password 2. Validates new == confirm 3. Calls FirebaseAuthService.changePassword(currentPassword, newPassword) 4. Service performs: - EmailAuthProvider.credential(user.email, currentPassword) - user.reauthenticateWithCredential(...) - user.updatePassword(newPassword)

Important: - No backend password-update endpoint is called. - Password storage/verification is fully Firebase Auth managed.

4. Logout flow

UI trigger: - SettingsScreen._showLogoutDialog()

Execution path: 1. Reset local providers: - SubscriptionProvider.reset() - RoomspaceProvider.clear() 2. Backend session logout: - ApiService.logout() -> POST /api/auth/logout 3. Firebase logout: - FirebaseAuthService.signOut() 4. Cookie cleanup: - ApiService.clearCookies() 5. Navigate to /login

Security model: - Backend session (session_id) invalidated server-side - Firebase local auth state cleared client-side

5. Roomspace management from Settings

Settings provides roomspace controls via provider/service chain:

  1. Load roomspaces: - RoomspaceProvider.loadRoomspaces() - GET /api/roomspaces

  2. Leave a roomspace: - RoomspaceProvider.leaveRoomspace(roomspace.id) - POST /api/roomspaces/:id/leave - Followed by loadRoomspaces(forceRefresh: true) for UI consistency

  3. Create/join/switch flows: - Delegated to existing roomspace feature routes/services - Settings acts as an entrypoint, not a separate backend flow

6. Payment detection settings flow

Page: - PaymentNotificationSettingsScreen

Capability areas: 1. Master enable/disable of payment detection 2. Notification monitoring toggle 3. SMS monitoring toggle 4. Minimum amount threshold 5. Allowed payment apps filter 6. Allowed merchants filter 7. Test-run helpers and payment history link

Data persistence: - Uses PaymentNotificationService and related APIs/storage paths - Works with payment-notification records and processing status endpoints

Related backend endpoints (from current API surface): - POST /api/payment-notifications - GET /api/payment-notifications - GET /api/payment-notifications/:id - PUT /api/payment-notifications/:id/processed - DELETE /api/payment-notifications/:id

7. Exact frontend method mapping (Settings)

  1. Open settings user/profile data: - SettingsScreen._loadUserData() - FirebaseAuthService.currentUser - CachedApiService.getUserProfile()

  2. Change password: - SettingsScreen._showChangePasswordDialog() - FirebaseAuthService.changePassword(...)

  3. Logout: - SettingsScreen._showLogoutDialog() - ApiService.logout() -> POST /api/auth/logout - FirebaseAuthService.signOut() - ApiService.clearCookies()

  4. Leave roomspace: - SettingsScreen._leaveRoomspace(...) - RoomspaceProvider.leaveRoomspace(...) - backend POST /api/roomspaces/:id/leave

  5. Payment notification settings: - PaymentNotificationSettingsScreen actions - PaymentNotificationService update/load flows - payment notification API family calls (create/get/update/delete)

8. Backend files involved indirectly via settings actions

  1. backend/handlers/auth.go - Logout handler for /api/auth/logout

  2. backend/handlers/roomspace.go - Leave roomspace action and related membership operations

  3. backend/handlers/payment_notification.go - Payment-notification CRUD/process endpoints used by settings-related monitoring features

  4. backend/middleware/auth.go - Protects settings-triggered APIs with session validation

9. Database tables used and purpose (Settings)

Primary tables touched by settings-driven operations:

  1. users - Profile data shown in settings (name/email) and account flags

  2. roomspaces - Roomspace entities displayed/managed from settings entrypoints

  3. roomspace_members - Membership updates during leave operations

  4. join_requests - Indirectly relevant when settings routes to join/manage flows

  5. payment_notifications - Detected transaction records used by payment notification settings/history/processing

  6. notifications - General app notifications indirectly tied to roomspace/payment actions

Session note: - session_id is cookie + in-memory session store, not a PostgreSQL table in current implementation.

10. One-line summary

Settings is a hybrid control plane: Firebase handles credential-level actions (change password), backend handles session and domain actions (logout, roomspace membership, payment-notification data), and providers/services keep UI state synchronized.
