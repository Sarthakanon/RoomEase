RoomEase Full Analytics + ML Bridge Flow

Technical Summary Paragraph

RoomEase analytics is implemented as a hybrid computation stack: deterministic aggregates and trend math run in the Go backend, while advanced predictions/recommendations/anomaly detection are delegated to an external ML bridge service via HTTP. The backend builds user-scoped (and optional roomspace-scoped) feature payloads from expense data, calls ML endpoints, then maps responses into frontend contracts. When ML is unavailable, the backend can return fallback analytics summary values and warnings, which keeps the app functional. In the current repository, ML model training code (CNN/RNN formulas, training loops, dataset row counts, and final training metrics) is not present; only the bridge integration contracts and metadata tables are included.

1. Analytics architecture in this repo

Core backend files: - backend/handlers/analytics_handler.go - backend/services/analytics_service.go - backend/config/ml_config.go - backend/models/analytics.go

Frontend consumer: - lib/features/analytics/presentation/analytics_page.dart - lib/services/analytics_service.dart - lib/services/smart_api_service.dart

Bridge config: - ML_API_URL and ML_API_PORT (backend/.env.example) - default bridge URL if not configured: http://localhost:5001

2. API endpoints exposed by backend analytics

Protected endpoints: - GET /api/analytics/summary - GET /api/analytics/trends - GET /api/analytics/predictions - GET /api/analytics/patterns - GET /api/analytics/anomalies - GET /api/analytics/recommendations - GET /api/analytics/roomspace/:id - POST /api/analytics/feedback

All support authenticated user context, and most support optional roomspace_id filtering (with membership validation).

3. ML bridge integration mechanics

Implemented in AnalyticsService.callMLAPI(...): - POST JSON payload to ML bridge endpoint - reads response body - non-200 response is treated as error

ML endpoints called by backend service: - /api/ml/predictions - /api/ml/recommendations - /api/ml/anomalies

Payload shape (from service): - user_id - optional roomspace_id - expenses[] as MLExpense - id - amount - category - date (YYYY-MM-DD) - user_uid

Bridge response objects expected: - predictions with confidence ranges and confidence score - recommendations with potential savings and priority - anomalies with anomaly score and confidence

4. Fallback behavior when ML is unavailable

In GetSummary handler: - base summary (total spend/top categories/trend) is computed from DB data - ML predictions/recommendations are attempted - if ML fails, response still returns success with fallback values and warnings

For dedicated endpoints (/predictions, /anomalies, /recommendations): - backend returns 500 when bridge call fails - this is what your logs currently show (ml ... unavailable)

6. Likely task types (inference from API schema)

Based on request/response contracts: - Spending predictions: regression-like output (predicted_amount numeric). - Recommendations: rule/model ranking output (optimization/recommendation task). - Anomalies: anomaly scoring/outlier detection (anomaly_score numeric).

This is an inference from contract shape, not proof of specific architecture (CNN/RNN/etc.).

8. Database tables used (analytics)

Core analytics tables: 1. analytics_cache - cached analytics JSON by user/roomspace/cache_type with expiry

  1. recommendation_feedback - user feedback on recommendation usefulness/application

  2. anomaly_acknowledgments - marks anomaly as normal/acknowledged

  3. ml_models - model metadata/versioning/status/metrics fields (accuracy, mae)

Input/source domain tables used by analytics computations: 5. expenses 6. expense_splits 7. roomspace_members 8. users

9. Why your app shows ML unavailable errors

Given your setup notes: - backend can be local or render - ML bridge is separate deployment (render)

Common causes visible from code/log behavior: 1. ML_API_URL misconfigured/unreachable from backend environment. 2. ML bridge running but endpoint contract mismatch. 3. Bridge timeout/error returning non-200. 4. Bridge deployed without required V2 model bundle.

10. One-line summary

Analytics in this repo is an API-orchestrated hybrid: Go computes deterministic summaries and delegates advanced forecasting/recommendation/anomaly inference to an external ML bridge; detailed model-training internals and final training metrics are not stored in this codebase.
